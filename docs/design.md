# 設計ノート — やねうら王フォークによるついたて将棋エンジン

2026-08-27 初版。以降、実測とセットで更新している(ベンチマークは 4.5 章)。

## 0. なぜフォークか

前作 tsuitate-bot (Rust) の調査メモ(`tsuitate-bot/docs/yaneuraou-lessons.md`)の結論:

> 「1局面に対する操作」はほぼ全部そのまま粒子に対して使えるが、
> 「木を掘る」系の技術は土台ごと無い。相手手が観測でしか分からないので木が張れない。2手読みが限界。

この「木が張れない」を突破するのが本作の主眼。**確定化サンプリング**では
粒子(=相手配置の具体的な仮説)ごとに完全情報の局面が確定するので、
その上では普通のαβ探索が任意の深さまで回せる。やねうら王から借りるのは:

- `Position` / `movegen` / 合法性判定(打ち歩詰め・自玉放置まで完全一致でサイトの反則判定と同じ)
- MaterialLv9評価関数(利き数・距離減衰・紐・玉周辺の穴。連載版の実測でR2700相当。外部ファイル不要)
- 利きの差分維持(`LONG_EFFECT_LIBRARY`)・1手詰め(`mate_1ply`)・弱3手詰め
- ビルド基盤(新エディション `TSUITATE_ENGINE` をMakefileに追加)

前作はGPL回避のため「アイデアだけ読んで自前実装」だったが、
本作はフォークなのでリポジトリ全体をGPLv3にして制約を外した。

## 1. 観測モデル(サイトの仕様の写し)

サーバー(tsuitate リポジトリ `judge.ts` / `events.ts`)の裁定:

- 反則 = **完全情報の通常将棋ルールで不正な手**(経路封鎖・打ちマス占有・二歩・
  打ち歩詰め・自玉放置すべて)。理由は通知されない。手番は変わらない。累計10回で反則負け
- 取った駒は盤上種別(成駒あり)で通知、取られたら**マスだけ**通知
- 王手宣言は正規手の直後に両者へ通知
- 合法手が無い(詰み・ステイルメイト)= 手番側の負け

エンジンの入力はこれで全部(`GameHistory` = `HistEvent` の列)。

### 王手宣言のタイミング

`game:check` は着手イベントの直後に同期的にemitされる。Socket.IOは同一接続でFIFOなので、
「次のイベントか`go`が来た時点で、直前の着手の王手宣言なし(=王手なし)が確定する」
というルールで遅延確定させる(`CheckAfter::Pending` → `Yes`/`No`)。
王手の**否定**も強い観測(粒子の玉位置を大きく絞る)なので、なし確定を必ず流すこと。

## 2. 信念状態(belief.h/cpp)

粒子 = ヒレの初期局面から観測と矛盾しない手順で到達できる完全局面1つ。
`Particle` は `Position` + StateInfoの列 + 自分が選んだ相手手列(`oppMoves`、リプレイ用)。
自分側の駒は全粒子で共通(完全既知、`OwnView`)。

### 更新則

| イベント | 粒子への操作 |
| --- | --- |
| 自分の正規手 | その手が合法・取った駒一致(盤上種別まで)・王手宣言一致の粒子だけ残して進める |
| 自分の反則手 | その手が**不正**な粒子だけ残す(合法だった粒子は矛盾) |
| 相手の着手 | 粒子上の合法手のうち観測(取られたマス・王手宣言)と整合する手を方策でサンプリングして進める。整合手ゼロなら死 |
| 相手の反則 | 制約なし(真の局面と無関係) |

### 相手手の方策(非千里眼prior)

相手手のサンプリングは「相手はこちらの駒が**見えない**」という生成モデルで行う:

```
P(相手の手 | 観測) ∝ prior(手) × [その手が真の盤で合法] × [観測と整合]
```

`prior` は相手自身の駒だけで決まる素朴な好み(駒種ごとの前進したさ・成り・
中央志向・玉は動かさない)。合法性と観測の整合は `consistent_opp_moves` が担う。
相手が実際に指せた手だけが観測されるので、この分解が正しい。

初版は「着手後の静的評価のsoftmax」だった。これは相手がこちらの駒を見て
取りに来る/当たりを避ける前提で、構造的なバイアスがある。さらに1手ごとに
`do_move` + 評価関数が要るため遅く、**回数の多い再生成リプレイでは
一様サンプリングに落としていた**(= フィルタと再生成で相手モデルが食い違い、
再生成した粒子だけ相手の指し手がでたらめ、という状態だった)。
priorは評価関数を呼ばないので、両方で同じ方策が使える。

温度120cp + 10%一様混合。`set opppolicy 0` で旧モデルに戻せる。

### 演繹層(deduce)

粒子の棄却だけでは弱い証拠を活かせないので、観測から**論理的に確定する**
情報を別に持ち、合成粒子の生成に効かせる。

- **確実な空きマス** — 自分の手が受理された = その経路(通過マス)・移動元・
  打ちの着地マスには相手駒がなかった。相手駒は相手の着手でしか動かないので、
  「相手の着手数」を時計にすれば
  `emptyStamp[sq] == oppMoveCount ⟺ いまも確実に空き` が厳密に成り立つ。
  差(陳腐化度)が小さいほど「まだ空きらしい」。
  平手初期局面は相手の配置も既知なので、対局開始時は相手駒のないマス全部が陳腐化度0
- **確実に相手駒がいるマス** — 相手が最後に自駒を取ったマス。
  それ以降に動いたのは自分の駒だけなので、取り返していなければ相手駒はまだそこにいる
- **反則からの割り出し** — 打ちは自駒を動かさないので自玉を晒せない。王手中でなく
  歩打ち(打ち歩詰めの可能性)でもない打ちが反則になったなら、着地マスが
  埋まっている以外に理由がない ⇒ そのマスに相手駒がいる(確実)。
  スライダー移動の反則は経路のどこかが埋まっている(ピンの可能性もあるので確率的)
- **現局面の反則との整合** — この手番で反則になった手が合法になる粒子は、
  真の局面ではありえない。合成粒子の棄却検査に使う


### 再生成の3段構え

粒子は必ず枯れる(特に自分の反則と捕獲の成り状態不一致で大量死する)。再生成は:

1. **部分若返り** — 死んだ粒子の相手手列を種に、**直近R手だけ**(R=2→4→8→16)
   整合サンプリングし直す。全滅の原因は直近の手にしか依存しないことが多く、
   ゼロからの全リプレイ(成功率がplyに対して指数的に落ちる)よりはるかに成功しやすい。
   種は墓場(リングバッファ256)から**最長生存**のものを優先する
   (古い短い種は「それ以降全部一様サンプリング」になり必ず序盤で死ぬ。実測済みの罠)
2. **緩和リプレイ** — 制約を弱い順に外す。relax1: 自分の反則制約と「王手なし」制約、
   捕獲駒の成り状態(生駒種一致までに緩める)。relax2: さらに「王手あり」。
   捕獲のマス・自手の合法性は絶対に外さない(駒勘定が壊れるため)。
   緩和粒子はp_legal推定を汚すので**最低限の数の確保にしか使わない**
3. **合成粒子** — 履歴を捨て、現在の駒勘定と王手状態だけ満たす配置を直接サンプリング。
   配置は一様ランダムではなく、駒種ごとの事前分布(相手から見た段・筋。歩は3段目、
   香は端の1段目、玉は自陣、…)に演繹の「空きらしさ」を掛けた重みで引く。
   演繹で確定したマス(相手が最後に取ったマス・反則から割り出したマス)は先に埋める。
   初版は空きマスから一様に引いていたので、歩が敵陣最奥にいるような配置を量産していた。
   駒勘定の保存則:
   - 相手側の駒総数(種別ごと) = 全体 − 自分の盤上 − 自分の持ち駒 (**厳密**)
   - 盤上/持ち駒の分割は観測不能(相手の打ちは見えない)。
     「取られた自駒の累計」を上限に、7割持ち駒と仮定してサンプリング
   - 王手を受けているときは王手駒を最後に明示配置する(偶然の王手を待つと失敗する)

  ※「自分の盤上駒数は初期配置が上限」という仮定は**誤り**(取った駒を打つと超える)。
  一敗地にまみれたので注意(駒勘定は必ず保存則で書く)。

時間配分: 同期(sync)は思考予算の40%を上限に、緩和ラダー80%+合成予約20%。

### 実測の効き(belief同士4局・500ms/手)

| 施策 | 0粒子思考 | 選択手の平均p_legal | 平均手数 |
| --- | --- | --- | --- |
| 素朴(全リプレイのみ) | 21% | 68% | 44 |
| +部分若返り | 15% | 75% | 66 |
| +種の質(最長優先) | 10% | 78% | 54 |
| +合成粒子+駒勘定修正 | **0%** | **89%** | **136** |

## 3. 手の選択(think.cpp)

```
combined(m) = p_legal(m) × E[squash(探索値) | mが合法な粒子] + (1 − p_legal(m)) × foulCp
```

- `p_legal` は全粒子での合法率。候補手 = 「自分の駒だけを考慮した」手
  (サイトのmove-hints.tsと同じ意味論)から、この手番で反則になった手を除いたもの
- stage1: 全候補×粒子24個の静止探索で粗く序列化 → 上位12手だけ
  stage2: 粒子48個×深さ2から反復深化(時間で打ち切り)
- 探索値は±2500cpで飽和、詰みは±3000(粒子平均が発散しないように)
- **反則コスト**: `-(350 + 60f) × 10/(10-f)`(f=反則累計)。
  さらに信念品質が悪いときに割増(緩和レベル×1.5倍、粒子数1/4未満で2倍)。
  固定コストだと終盤に反則予算を使い切って反則負けするスパイラルが実測で出る。
  **基礎値は初版の100から350へ引き上げた**。この競技は実質「反則予算10回の消耗戦」で
  (自己対戦はほぼ全局が反則負けで終わる)、反則1回は局面評価の数十cpではなく
  「持ち点の1/10 + 手番の損 + 信念の崩壊」に相当する。
  100のままだと「11%の反則リスクを150cpの得と交換する」ような取引を延々と続けて
  自分から反則負けに行く。実測は 4.5 章
- 0粒子時の保険は「見えない駒に当たりにくい手」(短い移動・打たない)優先。
  ただし現状の実装では合成粒子があるため実質的に到達しない

## 4. 審判つきアリーナ(arena.cpp)

完全情報のPositionを持つ審判がサイトのjudge.tsと同じ裁定でエンジン同士を対戦させる。
`belief`(本体)と `heuristic`(前進+成り+乱数 = サイト内蔵bot相当)が選べる。

```
printf "arena games 20 budget 300 particles 128 [p2 belief] [seed N] [verbose]\nquit\n" | ./YaneuraOu-by-gcc
```

`p1cfg <key> <val>` / `p2cfg <key> <val>` で**片側だけ**設定を上書きできるので、
同一バイナリ内でA/B対戦ができる(コードの変更も設定フラグ越しに切り替えれば同じ土俵で測れる)。

```
# 反則コストだけ変えて直接対決させる
printf "arena games 12 budget 200 particles 128 p2 belief p1cfg foulbase 350\nquit\n" | ./YaneuraOu-by-gcc
```

診断行(`belief diag[...]`)はプレイヤーごとに出る。勝敗は反則負けの分散が大きくて
12局程度では有意にならないので、**審判の完全情報と信念を突き合わせた指標**を主に見る:

| 指標 | 意味 |
| --- | --- |
| `king_acc` | 相手玉のマスを当てている粒子の割合(信念の芯の鋭さ) |
| `occ_rec` | 真の相手駒のうち、粒子が正しいマスに置けている割合(再現率) |
| `brier` | 選んだ手の `p_legal` の較正誤差。小さいほど「反則確率の見積もりが正直」 |
| `avg_p_legal` | 選んだ手の合法率(高いほど反則しにくい手を選べている) |
| `relax(0/1/2/synth)` | 緩和レベル別の思考回数。synthが多い = 信念が壊れて作り直している |

`king_acc` / `occ_rec` / `brier` は**1手番につき1回**しか数えない。
反則しても手番は変わらず同じ局面で指し直しになるので、指し直しまで数えると
「反則が多い設定ほど同じ局面を何度も数える」ことになり、指標が反則率で
重み付いてしまう(= 反則率とは別の証拠として使えなくなる)。
粒子が1つもない手番も 0 として数える(数えないと、信念が壊れやすい設定ほど
都合の悪い手番だけが標本から抜けて良く見える)。

**変更はこの数字とセットで評価すること**(前作の規律を継承)。

## 4.5 ベンチマーク

### 初版(2026-08-27)

モックサーバー(bridge/test/mock-server.ts)経由の直接対決。先後は1局ごとに交代。

| 対戦相手 | 結果 | 備考 |
| --- | --- | --- |
| 前進ヒューリスティック(サイト内蔵bot相当) | **20勝0敗**(反則2.2/局) | アリーナ、300ms/手 |
| 前作 tsuitate-bot (Rust, estimator v14相当) | **0勝6敗** | 本作の反則 3〜10/局、前作 1〜9/局 |

前作との差は主に**反則経済 = 信念の質**(前作のdocsが指摘していた律速がそのまま出た)。
実対戦ログから見つけて潰した致命パターン:

1. 成駒捕獲の通知種別の取り違え(モック側バグ)による粒子全滅
2. 「全候補が全粒子で不正」状態での情報ゼロの反則ループ → 信念破産検出で解決
3. 悪い局面で反則コストが「悪いが合法な手」を上回り確実反則を選ぶ → 確実反則の除外で解決

### 第2版(信念の質 + 反則経済)

出発点の計測: 自己対戦(200ms/手・粒子128)は**全局が反則負けで終わり**、
`king_acc`(相手玉のマスを当てている粒子の割合)は **13%** だった。
信念は「相手玉がどこにいるかほぼ分かっていない」状態で、反則がそのまま勝敗になっていた。

最終的な成績(レビューで見つかった不具合を全部直したバイナリで測り直したもの):

| 対戦相手 | 結果 | 備考 |
| --- | --- | --- |
| 前進ヒューリスティック(サイト内蔵bot相当) | **20勝0敗**、反則 **0.4/局** | 300ms/手。初版は同じ20勝0敗だが反則2.2/局。`king_acc` 74%、`brier` 0.008 |
| 初版と同じ設定<br>(`opppolicy 0 deduce 0 synthprior 0 foulbase 100`) | **35勝25敗**(60局) | 200ms/手・粒子128。20局×3(seed 101/201/301) |

初版設定との差(60局・思考9400回ぶん):

| 指標 | 第2版 | 初版設定 |
| --- | --- | --- |
| 勝敗 | 35 | 25 |
| **反則/思考** | **8.01%** | **10.02%** |
| `avg_p_legal` | 94% | 89% |
| `king_acc` | 17.0% | 12.7% |
| `occ_rec` | 41.0% | 36.7% |
| `brier` | 0.041 | 0.048 |

勝率58%は60局でもまだ有意とはいえない(両側 p≈0.2)。
一方で反則率の差は手ごとの標本が9400あるので明確
(2比率のz検定で z=3.4。1手あたりの反則が**相対20%減**)。
**確実に言えるのは「1手あたりの反則が2割減った」ところまで**で、
勝率はその帰結として58%に見えている、という読み方をしている。

決着理由の内訳(60局):

| 決着 | 局数 | 第2版から見た勝敗 |
| --- | --- | --- |
| 反則負け | 51 | **31勝20敗** |
| 詰み | 9 | 4勝5敗 |

勝ち星は**ほぼ全部が反則の消耗戦から来ている**(31/35)。
盤上の決着はほぼ互角(4勝5敗)で、しかも60局中9局しかない。
信念を良くしても「勝ちにいく」力はほとんど動いていないので、
次の律速はそちら(5章の0番)。

内訳(同一バイナリ内A/B。p1cfg/p2cfgで片側だけ設定を変えて対戦させたもの):

| 変更(p1 vs p2) | 勝敗 | 反則/思考 | brier |
| --- | --- | --- | --- |
| 新しい信念 vs 旧信念(合成粒子の事前分布は両者に入る) | **12勝0敗**(12局) | 5.4% vs 8.8% | 0.043 vs 0.061 |
| 新しい信念 vs 旧信念(事前分布も初版に戻す) | 7勝5敗(12局) | 5.8% vs 6.7% | 0.046 vs 0.047 |
| 合成粒子の事前分布 あり vs なし(演繹オン) | 9勝1分10敗(20局) | 5.9% vs 7.4% | 0.041 vs 0.051 |
| `foulbase` 350 vs 800 | **13勝7敗**(20局) | 7.1% vs 8.0% | 0.043 vs 0.054 |
| `foulbase` 350 vs 150 | 11勝9敗(20局) | 8.5% vs 9.0% | 0.050 vs 0.049 |

※ 12〜20局の勝敗は標準偏差が2局前後あり、それ単独では何も言えない
(同一設定同士でも 9勝11敗〜12勝8敗まで振れる)。
上の表は**勝敗と反則/思考・brier が同じ向きに動いている行だけを結論として扱っている**。

読み取れたこと:

- **反則の値付けの最適値は信念の質に依存する**。初版の `foulBaseCp = 100` が
  低すぎるのは変わらないが、段の向きのバグを直して信念が良くなったあとは
  800まで上げると逆に悪化した(350が13勝7敗。反則/思考も 7.1% vs 8.0% で同じ向き)。
  150〜400あたりは平ら。信念が悪いほど「とにかく安全な手」に倒す価値が上がる、
  という関係らしい
- **合成粒子の事前分布は、演繹層とセットでないと効かない**。演繹を切った状態では
  事前分布ありのほうが反則が増える(6.7% → 8.8%)。
  「確信をもって間違った場所に駒を置く」ぶん、一様配置より悪くなるということ。
  演繹オンなら手ごとの指標は一貫して良くなる(反則/思考 5.9% vs 7.4%、
  `brier` 0.041 vs 0.051)が、**勝率は20局で 9勝1分10敗の互角**で、
  盤面の強さに変換しきれていない
- 信念側の改善は `avg_p_legal` を 89% → 94% に上げた。
  ただし上の決着内訳のとおり、勝ち星はほぼ反則の消耗戦から来ていて、
  盤上の決着はほとんど動いていない
- **勝率は20局では当てにならない**。同じ設定同士で seed を変えただけで
  9勝11敗 / 12勝8敗 / 11勝9敗 と振れる(標準偏差が2局強あるので当然)。
  20局のA/Bで出た「勝ち越し」は、手ごとの指標が同じ向きに動いていないかぎり
  信用しないほうがよい

### レビューで見つかった不具合(重要)

第2版の最初の計測は、以下の不具合を抱えたまま取ったものだった。
上の数値はすべて修正後に測り直してある。

1. **事前分布と演繹の段が反転していた(致命)** —
   `relative_rank(c, r)` は「c の最奥が8」なので、「相手から見た段」を得るには
   `relative_rank(us, r)` を引く必要がある。`relative_rank(opp, r)` を使っていたため、
   相手玉の初期マス(5一)の重みが40であるべきところ1、こちらの最奥が1であるべき
   ところ40になっていた。`OwnView::reset` も同じ向きで、相手の初期20マスを
   「確実に空き」と刻んでいたので、`deduce=1` では合成粒子が相手陣に駒を置けなかった。
   **入れたつもりの改善が逆向きに効いていた**
2. **合成粒子の事前分布は `deduce` フラグで切れなかった** — A/Bの「旧信念」側にも
   入り込んでいたので、初版との比較になっていなかった。`synthPrior` を追加して分離した
3. **部分若返りの高速化が入っていなかった** — `opp_move_consistent` が
   ヘッダに宣言だけ残っていて、実装も呼び出しもなかった
4. **診断を `choose()` の前に取っていた** — 信念の同期・再生成は `think()` の中で
   走るので、同期前の粒子を今の真の盤と比べていた。
   この変更が効かせたい経路そのものを測り損ねていた(修正前の `king_acc` の
   絶対値は修正後と比較できない)

教訓: **フラグで切れない変更はA/Bの対照側にも入り込む**。
「片側だけ設定を変えて対戦させる」harnessを作っただけでは足りず、
新しい挙動を全部フラグの後ろに置いて初めて切り分けになる。

## 5. 既知の限界と次の一手

0. **千里眼バイアス(相手手方策は解消済み、探索側は未着手。いま最優先)** —
   相手手のサンプリングは非千里眼priorに移した。しかし確定化探索は依然
   「相手はこちらの駒が見える」前提で、こちらの駒を過剰に危険視する
   (=前に出られない)。60局で盤上の決着が9局しかなく4勝5敗にとどまるのは、
   ここが効いている可能性が高い。相手の視界をモデル化した探索側の補正が次の大玉
1. **相手手priorが手書きの線形式** — 前作のopp_move NN/joseki風prior相当に
   置き換える余地が大きい。`fast_policy_score` の重みは未較正(勘)
2. **重み無しの粒子** — 全粒子等重み+棄却。観測尤度による重み付け(SIR)にすると
   王手否定などの弱い証拠を捨てずに使える。
   `pLegalPrior`(p_legalのシュリンク)は入口だけ作ってある(既定オフ、未検証)
3. **妨害マップ(`blockCp`)が未較正** — 相手の反則を誘う配置への加点。
   機構は入れたが `blockcp 2000` は勝率中立だった。
   相手の「指したい手」を一様と仮定しているのが粗すぎるはずで、
   非千里眼priorで重み付けするのが次の一手
3.5. **(実測で確認済み)信念の良さが盤面の強さに変換できていない** —
   初版設定との60局で、勝ち星35のうち31が反則負け由来。盤上の決着は
   4勝5敗でほぼ互角、しかも9局しかない。1手あたりの反則を2割減らしても
   総合は58%にとどまる。0番(探索側の千里眼バイアス)が最優先
4. **探索が自前の簡易negamax** — やねうら王本体の`YaneuraOuWorker`(LMR・TT・history付き)を
   粒子探索に使う配線は未着手。stage2の深さを上げるならこちらが本筋
5. **並列化されていない** — 粒子はほぼ完全に独立なので、再生成も確定化探索も
   コア数ぶん並列にできる。実対局の予算(2.4秒/手)なら粒子数を数倍にできるはず
6. **NNUE** — MaterialLv9で始めたが、NNUE評価(halfKP)に差し替え可能な構造。
   評価ファイルの配布と強さ/速度のトレードオフは未検証
7. **オフライン再現** — 前作のscenario(実戦の局面再現)に相当する仕組みは未移植。
   実対局の記録(ブリッジ側でJSONL化)から始めるのがよい
8. **前作との再戦が未実施** — 第2版になってからの tsuitate-bot (Rust) との
   直接対決はまだ測っていない。初版は 0勝6敗
