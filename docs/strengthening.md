# 強化設計 — 第3版に向けて

2026-08-28。第2版のベンチマーク(design.md 4.5章)を踏まえた、次に強くするための設計。
各施策は「何が問題か → どう直すか(コードの接続点) → どう測るか(採用ゲート)」の
3点セットで書く。**フラグで切れない変更は対照側に混入する**(4.5章の教訓)ので、
新しい挙動はすべて `Config` のフラグの後ろに置く。

## 0. 現状の診断 — どこが律速か

第2版の実測(60局・決定5500回)から確定していること:

- 信念の改善は反則を減らした(8.0% → 6.4%/決定)が、**盤上で勝つ力は動いていない**。
  盤上決着は60局中12局・6勝6敗。勝ち星38のうち32は反則の消耗戦由来
- 中盤の信念は**7割が合成粒子**。履歴リプレイは中盤までに死に絶えるので、
  信念の上限は合成粒子の質(事前分布×演繹)が決めている
- `king_acc` 17%・`occ_rec` 38%。信念はまだ粗いが、brier 0.036 で
  「反則確率の見積もり」としてはすでにそこそこ正直

ここから、強さの構造を3つの階層に分けて考える:

1. **探索が返す値が歪んでいる**(千里眼バイアス)— 信念がいくら正しくても、
   その上で回す探索が「相手はこちらの駒が見える」前提なら、
   前進・王手・妨害の価値が体系的に過小評価される。**いま最優先**(§1)
2. **観測を捨てている** — 相手の反則は現状「カウントのみ」で粒子に何も効かせていないが、
   実際には相手の駒配置についての証拠である。等重み粒子のままでは弱い証拠を使えない(§2)
3. **計算資源を使い切っていない** — 単スレッド・TTなしの簡易negamaxで、
   実対局の予算(約2.4秒/手)に対して粒子数も深さも1桁足りない(§3)

当初の優先順位は 1 → 3(並列化)→ 2 → 3(TT)→ 4 だった。
理由は「§1は勝敗の構造(盤上決着の少なさ)に直接効く唯一の施策で、
§2・§4の効果は§1が入って初めて盤面の強さに変換される」という読み。

> **この読みは実測でほぼ否定された(1.11章)。** §1を入れると盤上で戦う頻度は
> 約2倍になり、反則も有意に減り、信念も鋭くなる。
> **しかし233局で勝率は54.1%(有意でない)、盤上の勝敗は42勝41敗で互角。**
> 採用ゲートの60%には遠い。千里眼バイアスは盤上の決着を避けさせていたが、
> 盤上で負けさせてはいなかった —— 方向は正しかったが効果量が足りない。
> **改訂後の優先順位は 3(計算資源)→ 2(SIR)→ 4(prior較正)**。
> 詳しくは §7 の表と 1.11章。

## 1. 【最優先】探索の非千里眼化(`oppmodel`)

### 1.1 問題の定式化

確定化探索(dsearch.cpp)は粒子上の完全情報negamaxなので、相手ノードでは
「相手にとっての最善手」を選ぶ。これは相手がこちらの駒を全部見ている前提であり、
ついたて将棋の現実とは体系的にずれる:

- **前進の過小評価** — こちらが駒を進めると、探索内では相手が必ず当たりを付けて
  取りに来る。実際の相手には見えていないので取られない確率が高い。
  結果「前に出ない」bot になる(盤上決着12/60の主因と推定)
- **王手の過小評価** — 探索内の相手は完全な逃げ方を知っている。実際の相手は
  王手宣言だけ受け取り、どの駒からの王手かも分からないので、**逃げ損ねて反則を
  量産する**(自玉放置)。王手はついたて将棋では材料以上に強い手だが、いまの探索は
  それを織り込めない
- **妨害の無価値化** — 相手の指したい手の経路や打ちマスをこちらの駒で塞ぐと
  相手は反則する(=予算1/10を失う)。探索内の相手は反則しないので、この価値がゼロになる。
  `blockCp` はこれを外付けの加点で近似しようとしたものだが、未較正で勝率中立だった

一方、信念側の相手モデルはすでに非千里眼prior(`fast_policy_score`)に移行済みで、
「相手の手は相手自身の駒だけで決まる素朴な好み × 合法性フィルタ」という生成モデルが
実測で機能している(反則率2割減の主因)。**探索も同じ生成モデルに揃える**のが本施策。

### 1.2 設計

相手ノードの値を min(negamaxのmax)から**期待値+反則期待ボーナス**に変える。

相手の意図分布: 相手の視界(粒子上の相手駒のみ、`pos.pieces(opp)`)で生成した
指したい手(移動+打ち)に `fast_policy_score` の softmax(温度・ε一様は信念と共通の
`policyTemp`/`policyEps`)を掛けたもの。これを q(m) とする。意図が真の盤で不正なら
反則→指し直しなので、

- 合法な意図の質量 p_ok = Σ_{m: 粒子上で合法} q(m)
- 実際に指される手の分布 q̂(m) = q(m)/p_ok(合法な m のみ)
- この手番の相手の期待反則回数 E[fouls] = (1 − p_ok)/p_ok(幾何分布近似。
  信念のリプレイは試行済み手を除外するが、探索では復元抽出の近似で十分)

相手ノードの値(negamaxの符号系のまま、相手視点):

```
V_opp = (1−λ) · Σ_{m ∈ S} q̂(m)·V_child(m)  +  λ · max_{m ∈ S} V_child(m)
        − fG · E[fouls]
```

ここで `V_child(m) = −search(子局面)` は「相手にとっての」その応手の値。
S は展開する応手の集合(下記)。

> **初版の式の訂正**: 最初にこの節を書いたとき λ 項を `min` と書いていたが、
> 相手視点の値を最大化するのが千里眼の相手なので `max` が正しい
> (「こちらの値を最小化する」= 「相手の値を最大化する」を書き写す際に符号を落とした)。
> `min` のままなら λ 項は「相手がわざと最悪手を指す」項になり、
> 混合の意味が逆になっていた。実装は `max` で入れてある。

- **top-k打ち切り** — q̂ の上位 k 手だけ子を探索して正規化し直す。
  k は `oppReplyK`(1手目の相手ノード、既定6)/ `oppReplyKDeep`(それ以深、既定3)。
  相手ノードの分岐が 〜80 → k に落ちるので、期待値化しても探索は**軽くなる**方向
- **λ混合(`oppLambda`。設計時の既定0.25 → 実測後の既定は 0。1.6章)** —
  純粋な盲目相手モデルは逆方向に楽観的すぎる、と設計時は考えた。
  実際の相手(人間・他bot)は自分なりの信念でこちらの駒位置を推測してくるので、
  max との混合で「部分的に見えている相手」を粗く近似する。λ は §7 のA/Bで較正する。
  max は同じ集合 S の上でとる(追加の探索コストなし)
- **S には最良の捕獲を必ず入れる** — 設計初版は λ 項が top-k の上でしか取れない
  ことへの手当てを `oppMinProbe`(浅い千里眼プローブ)として構想していたが、
  実装では「合法な意図のうち最も価値の高い捕獲」を S に1手足すだけにした。
  漏れて困る千里眼的な殺し手はほぼ「こちらの駒が取られる筋」であり、
  それはprior順では下位に沈むが MVV では自明に見つかる。探索コストは1手ぶん、
  期待値側の重みは元の q のままなので(prior が低い手なので)期待値はほとんど動かない
- **stage1 にも同じモデルを掛ける(`oppReplyKStage1`、既定2)** — 設計初版で
  見落としていた経路。stage1 は全候補を静止探索で粗く序列化して上位12手だけを
  stage2 に送るが、その静止探索が千里眼のままだと「進めた駒は必ず取られる」順に
  並ぶので、**相手モデルが評価したい前進手が stage2 に届かない**。
  stage1 も深さ1の探索(相手ノード1つ + 子のqsearch)に差し替える。
  ただし stage1 は全候補×粒子で回るので k は小さく(既定2)。
  `oppReplyKStage1 0` で従来の千里眼qsearchに戻せる(この経路自体のA/B用)
- **反則期待ボーナス fG** — 相手の反則1回の価値。§5の統一反則経済で
  `foul_value(view.oppFouls)`(こちらの `foulCp` と同じ式の鏡像)に
  `foulGainScale` を掛けたものを使う。
  王手中の相手ノードでは合法手=逃げ手のみになり p_ok が急落するので、
  **王手が「相手の反則期待」として自動的に加点される**。外付けだった `blockCp` は
  この項に吸収される(`oppmodel>=1` のとき `blockBonus` は無効化して二重計上を防ぐ)。
  `E[fouls]` は `oppFoulCap`(既定2.0)で頭打ちにする。`(1−p_ok)/p_ok` は
  p_ok→0 で発散するが、p_ok は手書きpriorに依存する粗い量なので、
  青天井にすると「相手は必ず反則する」と信じ込んだ楽観的な読み筋だけが選ばれる
- **段階導入** — `oppmodel 0`: 現状(千里眼min)。`oppmodel 1`: 自分の候補手の直後の
  相手ノード(ply=1)だけ期待値化し、それ以深は通常のαβ(枝刈り温存)。
  `oppmodel 2`: すべての相手ノードで期待値化(k は deep 用の小さい値)。
  バイアスの大半は最初の相手応手(進めた駒が即取られる)にあるので、
  まず 1 で効果を測る。期待値ノードはαβの窓が使えない(子は全窓で探索)ため、
  2 のコストは 1 の実測を見てから判断する。Star1系の枝刈りは将来課題
- **詰みスコアの扱い** — 期待値に混ぜる前に子の値を `squash_cp` 相当で飽和させる。
  「相手が3割の確率で詰みを見逃す」は大きな正の値であって詰みスコアではない
- **qsearch は当面千里眼のまま** — 静止探索の相手捕獲は保守的な床として残す。
  期待値化の対象は search() の相手ノードのみ。qsearch側の補正は
  効果測定後の別フラグ実験とする
- **王手中のprior(`oppCheckPrior`、既定0)** — 実装中に気づいた別軸の穴。
  王手宣言は**両者に**届くので、相手も「自分が王手されている」ことは知っている
  (どの駒からかは見えない)。ところが素のpriorは玉を動かす手を −250 で強く嫌うので、
  王手中の相手の応手分布が実態から大きくずれ、p_ok も過大に見積もられる。
  `oppCheckPrior 1` で「王手中は玉を逃がしたがる(+400)・合駒は当てずっぽう(−200)」に
  切り替える。既定を0にしてあるのは、この prior を信念側(`sample_policy`)と
  共有しているため —— 1にすると信念の挙動まで変わるので、`oppmodel` とは
  **独立にA/Bすること**(4.5章の「フラグで切れない変更は対照側に混入する」の系)

実装の接続点(実装済み):

- 相手の意図列挙 `enumerate_opp_intents()` と prior `fast_policy_score()` を
  `tsuitate_common` に置き、信念の `sample_policy` と共有する。
  `fast_policy_score` は belief.cpp の無名名前空間にあったものを移した
  (探索と信念で相手モデルが分岐しないことが非千里眼化の要)
- **意図の集合は相手の合法手の上位集合になる**、という性質に依存している。
  見えないこちらの駒はスライダーの利きを**伸ばす方向にしか効かない**ので、
  相手視界での生成は真の合法手を必ず含む。したがって
  「合法な意図がゼロ ⟺ 相手に合法手がない ⟺ 相手の負け」が厳密に言え、
  `mated_in` を返す経路が正当化される
- `DSearch` に `cfg` / `us` / `foulGain` / `oppK1` を持たせ、`search()` の
  先頭で相手ノードだけ `opp_node()` に分岐する。**`mate_1ply` より前**に分岐すること:
  「相手が1手詰めを見つける」のはこちらの玉が見えている前提そのもので、
  この施策が消したいバイアスの中心にある
- 期待値ノードの子は全窓で探索する(重み付きなのでαβ窓で打ち切れない)。
  `nodesLimit` の保険はそのまま効かせる
- 子の値は期待値に混ぜる前に `squash_cp` で飽和させる。混合値は**すでに squash 済みの
  空間**(詰み=±3000 / 通常=±2500 のスケール)にいるので、`opp_node` の返り値は
  ±3000 まで許し、`DSearch::rootMixed` を立てて think() 側で**二重に squash しない**。
  ここを ±2500 に丸めていたため、ply=1 より深くで見つけた詰みが通常評価の上限と
  同じ値に潰れていた(4巡目のレビューで発覚。1.7章末尾)。
  本物の詰みスコアを返すのは「相手に合法手がない」経路と、
  相手の合法応手を網羅して全部同じ決着だった2経路だけ

### 1.3 計測と採用ゲート

- アリーナ診断に**決着内訳**を追加する: `decided(board/foul)` と盤上決着のみの勝敗。
  §0のとおり「盤上で勝てるようになったか」が本施策の成否そのものなので、
  総合勝率より先にこれを見る
- fG の較正検査: 探索が予測した相手の期待反則数と、審判が記録した実際の
  相手反則数を手番ごとに突き合わせる(brierと同じ発想の較正指標)。**未実装**
- 採用ゲート: 対第2版既定(`oppmodel 0`)で 60局×3seed、
  (a) 盤上決着率が有意に上がる、(b) 総合勝率 ≥ 60%、(c) 反則/決定が悪化しない。
  λ・k・fG は同一バイナリの `p1cfg`/`p2cfg` A/Bで振る

### 1.4 実測(2026-08-28): 既定値では**ゲート不合格**

`oppmodel 1`(既定 λ=0.25 / k=6 / stage1 k=2 / fG=foul_value(oppFouls))を
第2版既定(`oppmodel 0`)と 20局×3seed = 60局、200ms/手・粒子128 で直接対決させた結果:

| 指標 | oppmodel 1 | oppmodel 0 | 判定 |
| --- | --- | --- | --- |
| 勝敗 | **25勝1分34敗**(41.7%) | — | ✗ ゲート(b) 60%に届かない |
| **盤上決着** | **11局中 3勝8敗** | | ✗ ゲート(a) むしろ負け越し |
| 盤上決着率 | 18.3%(11/60) | | ✗ 第2版の20%から動かず |
| 反則/決定 | 6.08% | 5.87% | △ 悪化はしていない(z=+0.51、差なし) |
| `avg_p_legal` | 97.68% | 97.87% | 差なし |
| `king_acc` | 13.5% | 15.4% | |
| `occ_rec` | 34.6% | 31.2% | |
| `brier` | 0.041 | 0.042 | 差なし |

**不合格。既定は `oppmodel 0` のまま据え置く**(実装はフラグの後ろに残す)。

読み取れたこと:

- **反則側の指標が一切動いていない**(反則率 6.08% vs 5.87%、brier も同じ)。
  つまりこの施策は「相手の反則を誘う」ようには効いていない。
  fG の項が意図した働きをしていないか、候補手の序列を変えるほどの
  差分になっていないかのどちらか
- **悪化しているのは盤上**(盤上決着11局で3勝8敗)。
  施策が直そうとした当の指標が逆に動いた。反則率が動いていないので
  「危ない王手を追って反則を増やした」という筋ではなく、
  **確定化探索の楽観化そのものが positional に損をしている**と読むのが自然。
  determinization の既知の弱点(strategy fusion)と同じ向きの失敗で、
  相手が punish してこない前提で駒を前に出し、じわじわ material を失っている疑い
- 20局×3seedでも勝率の標準偏差は3局強あるので 41.7% は「有意に悪い」とまでは
  言えない(z=−1.17)。ただし**ゲートは「有意に良い」ことを要求する**ので、
  この結果では通らない
- 6局の試走では反則率 4.87% vs 8.38% と大差が出ていた。**60局で消えた**。
  4.5章の「20局の勝ち越しは信用しない」は反則率にもそのまま当てはまる

正当性の検証(こちらは合格):

- `checkintents` で「意図の集合 ⊇ 相手の合法手」を 35,969局面・合法手1,435,236手で確認。
  `missing=0`。`opp_node` が `mated_in` を返す経路は健全
- `oppmodel 0` の経路は従来と同一(`fast_policy_score` の移動と `foul_value` への
  一本化はいずれも既定値で恒等)

### 1.5 切り分け: **害はfG(反則利得)の項。期待値化そのものは効いている**

同じ土俵(20局×3seed = 60局、対 `oppmodel 0`)で2つの仮説を分離した。

| 設定 | 勝率 | **盤上決着** | 盤上の勝敗 | 反則/決定 |
| --- | --- | --- | --- | --- |
| `oppmodel 0`(対照) | — | 18〜20% | — | 5.8〜5.9% |
| `oppmodel 1`(既定) | 41.7% | 18.3% | 3勝**8敗** | 6.08% |
| + `opplambda 0.6` | **36.7%** | 16.7% | 3勝7敗 | **6.80%**(z=+2.1 悪化) |
| + `foulgain 0` | 41.7% | **35.0%** | **12勝9敗** | 6.23% |

読み取れたこと:

- **λ を上げる(千里眼寄りに戻す)と全部悪くなる**。勝率36.7%、反則率も有意に悪化。
  「盲目モデルが楽観的すぎるから盤上で負ける」という仮説は**棄却**。
  期待値化の向きは正しく、むしろ千里眼側に戻すほど悪い
- **fG を切ると盤上決着率が 18.3% → 35.0% と倍増し、盤上の勝敗が
  3勝8敗 → 12勝9敗に反転する**。§1が直そうとした当の指標
  (ゲート(a) = 盤上で勝てるようになったか)は、**fGを外した形で満たされた**。
  第2版から2年ぶんの停滞(「信念を良くしても勝ちにいく力が動かない」)が
  ここで初めて動いた
- つまり **1.4章の失敗はfGの項が単独で起こしていた**。
  相手の期待反則を局面評価に足し込むと、bot は「相手が反則しそうな局面」を
  求めて盤上の決着を避けるようになり、その局面で勝てない。
  相手の反則は**こちらの手番の価値ではなく相手の手番の損**なので、
  こちらの局面評価に同じ通貨で足すという値付け自体が誤っていた疑いが強い
- ただし総合勝率は 41.7% のままで、**反則戦では13勝24敗と負け越している**。
  盤上で勝てるようになった一方、反則の規律が緩んだ(反則/決定 6.23% vs 5.81%)。
  この競技は決着60局中37局が反則負けなので、ここを取り戻さないと総合では勝てない

### 1.6 較正: λ は 0 が最良、反則の値付けは締め直しが要る

同じ土俵(20局×3seed = 60局、対 `oppmodel 0` 既定)での続き。
すべて `foulgain 0`(1.5章でfGは有害と判明したため)を土台にしている。

| 設定(すべて + `foulgain 0`) | 勝率 | 盤上決着 | 盤上勝敗 | 反則/決定 (p1 vs p2) |
| --- | --- | --- | --- | --- |
| λ=0.6 (fGあり、1.5章) | 36.7% | 16.7% | 3勝7敗 | 6.80% vs 5.90%(z=+2.1) |
| λ=0.25(既定) | 41.7% | 35.0% | 12勝9敗 | 6.23% vs 5.81%(z=+1.0) |
| **λ=0.0** | **53.3%** | **36.7%** | 11勝11敗 | **5.56% vs 6.47%(z=−2.1)** |
| λ=0.25 + `foulbase 600` | 50.0% | 31.7% | 9勝10敗 | 5.14% vs 5.76%(z=−1.7) |

- **λ は単調**(0.6 → 0.25 → 0.0 で勝率 36.7% → 41.7% → 53.3%)。
  相手ノードに千里眼の最善応手を混ぜるほど悪い。
  **λ の既定は 0.25 ではなく 0.0 にすべき**で、そもそも λ 混合という機構自体が
  要らない可能性がある(「実際の相手は部分的にこちらを推測してくる」という
  設計時の直感は、少なくともアリーナの相手に対しては支持されない)
- **λ=0.0 では反則率まで有意に良くなる**(5.56% vs 6.47%、z=−2.1)。
  1.5章の λ=0.25 では反則率が悪化していたので、これも λ の副作用だった
- **自分の反則の値付けは締め直しが要る**。`foulbase 600` は λ=0.25 のままでも
  反則率を 6.23% → 5.14% に戻し、勝率を 41.7% → 50.0% に引き上げた。
  4.5章の「350が最適(800は悪化)」は **bot が受動的だった時代の較正**であり、
  盤上で戦うようになると最適値が上がる。
  「最適値は信念の質に依存する」に加えて「**探索の攻撃性にも依存する**」

#### レビューで見つかった不具合(重要): 反則項の飽和

`opp_node` の返り値は ±2500cp にクランプしているのに、そこへ足す相手反則項
`foulGain × E[fouls]` には上限がなかった。`foul_value` は 10/(10−f) で急騰するので:

| 相手の反則累計 | `foul_value` | × `oppFoulCap` 2.0 |
| --- | --- | --- |
| 0 | 350 | 700 |
| 4 | 983 | 1967 |
| 7 | 2567 | **5133** |
| 9 | 8900 | **17800** |

**相手が反則を6回を超えて重ねると、全相手ノードがクランプに張り付いて
位置評価が丸ごと消える**。反則経済が勝敗を決める終盤でそうなる。
再現(修正前): `oppmodel 2` で相手反則 0/4/7/9 のときの評価が
442 / 1112 / 1646 / 1646 と、7回と9回で同値になっていた。

**1.4〜1.6章の「fGは有害」という結論はこの飽和バグに交絡している**。
`oppFoulMaxCp`(既定800)で上限を掛けて修正し、再測定した(下記)。
修正後は 807 / 875 / 879 / 895 と飽和しない。

ただし上限を掛けるのは対症療法である。**本質は通貨の取り違え**で、
`foul_value` は「持ち点の1/10」のスケール、局面評価は ±2500 に飽和させたスケールで、
この2つを探索木の中で足すこと自体に無理がある。
think.cpp が自分の反則コストを**決定の段(`combined`)で**扱っているのと同じく、
相手の反則期待も**根で候補手ごとに集計して `combined` に足す**のが筋。
fG を復活させるならその形にすべき(§1の次の設計)。

同じレビューで直した他の不具合:

- **深いところで見つけた詰みが ±2500 クランプで「ふつうの優勢」と同点になる** —
  最終選択の乱数タイブレーク(0〜4cp)が詰みを蹴りうる。
  「選んだ応手が相手の合法手を網羅していて、そのすべてが詰み」のときだけ
  本物の詰みスコアを返すようにした(終盤は相手の合法手が k 以下に減るので実際に効く)
- **`blockCp` が `oppModel > 0` で無言のうちに無効化されていた** —
  `p1cfg oppmodel 1 p1cfg blockcp 60` のようなA/Bが丸ごと無意味になる。
  そもそも二重計上が起きるのは相手ノードが実際に反則の価値を数えているとき
  (`foulGainScale > 0`)だけなので、無効化の条件をそちらに直した。
  黙って効かなくなる場合はアリーナ開始時に注記を出す(`regenfloor` と同じ扱い)
- **`block_map` が共有の `enumerate_opp_intents` を使っていなかった** —
  ヘッダのコメントは「3か所で共有する」と書いてあるのに独自に列挙していて、
  成り変種と `piece_can_stay` を落としていた。共有版に置き換えた

#### 2度目のレビューで直した不具合

- **こちらが詰まされる側の詰みが保存されていなかった** — `exhaustive && allMate`
  (相手の合法手を網羅して全部詰み = こちらの勝ち)は詰みスコアを返していたが、
  **逆向き**(どの応手を選んでもこちらが詰まされる)は ±2500 クランプに潰れて
  「ふつうの劣勢」と同点になっていた。乱数タイブレーク(0〜4cp)が
  詰まされる筋を選びうる。対称な `exhaustive && allTheyMate` を追加した。
  どの応手でも詰まされるなら相手の視界に関係なく負けなので、これは確率ではなく確定
- **`blockCp` の抑止条件に `oppReplyKStage1 > 0` が抜けていた** — 上位手を切るのは
  stage1 なので、`oppreplykstage1 0`(stage1は千里眼qsearchのまま)だと
  妨害の価値がstage1のどこにも入らず、**妨害狙いの候補手が stage2 に届く前に
  切り落とされる**。抑止は3条件が揃ったときだけにし、
  揃わないとき(=二重計上になるとき)もアリーナが注記を出すようにした
- **`oppLambda = 1` を「従来の千里眼」と書いていた** — `opp_node` の max は
  展開した応手集合(prior上位k手 + 最良の捕獲)の上でしか取らず、
  `mate_1ply` も αβ の窓も通らないので、`oppmodel 0` とは別物。
  A/Bの対照に使えると誤読させるコメントだったので訂正した
- **`blockCp` のヘッダコメントが実際の抑止条件と食い違っていた**(「`oppModel >= 1` で
  無効化」と書いてあったが実際は3条件)
- **`checkintents` が不正・範囲外の引数を黙って既定値に落としていた** —
  `checkintents 500000 200` が既定の200局を回して `missing=0` を返し、
  「10万局で検証した」と誤読させる。**不変条件の検証コマンドが規模を偽るのは
  最悪の壊れ方**なので、このファイルの規約どおり検証して報告・中止するようにした
- **`block_map` が `inCheck` に反対側の王手状態を渡していた** — 粒子は常にこちらの
  手番なので、相手が王手されていることは定義上ありえない(`pos.in_check()` は
  こちら側の状態を返す)。現状は `block_map` が prior スコアを読まないので無害だが、
  3か所で共有する生成器に誤った引数が刺さったままなのは事故のもと。`false` に直した

#### 3度目のレビューで直した不具合

- **`exhaustive && allTheyMate` を「確定した敗北」と扱っていたのが誤り** —
  `allWeMate`(こちらの勝ち)側は**無条件に健全**である。相手が何を指しても詰むし、
  相手が反則しても局面は変わらず指し直しになるだけ(むしろ相手の予算が減る)。
  ところが**逆向きは対称ではない**。相手にはこちらの駒が見えないので、
  こちらを詰ます合法手に辿り着く前に反則を重ねる。しかも `exhaustive` になるのは
  相手の合法手が少ない局面 = `p_ok` が小さい局面で、**まさに相手が反則を量産する状況**。
  相手の反則累計が多ければ真の決着は「こちらの反則勝ち」でありうる。
  短絡すると反則項(`v -= min(foulGain·E[fouls], oppFoulMaxCp)`)を飛ばしてしまうので、
  **反則の価値を数えていない設定(`foulGain == 0`、既定)のときだけ**短絡し、
  数えているときは混合に委ねるようにした
- **`decided:` 行が p1/p2 を欠いていた** — 同じ差分で `winner=` のほうは直したのに
  内訳行を直しておらず、A/B(両者とも種別名が "belief")で勝った側が読めなかった。
  この内訳は p1cfg/p2cfg のA/Bのためにこそ存在するので致命的に読めない
- README に新設定9個のうち3個しか載っていなかったので全部記載。
  設計文書の古い既定値(λ=0.25 / `foulGainScale` 1.0)にも実測後の値への注記を付けた

#### 4度目のレビューで直した不具合(どちらも評価の順序が逆転する)

- **確定した敗北がただの劣勢より高く評価されていた** — 3巡目で
  `exhaustive && allTheyMate` の短絡に `foulGain <= 0` の条件を付けたのは**誤りだった**。
  `foulgain > 0` だと短絡を飛ばして混合に落ち、
  `3000 − min(foulGain·eFoul, oppFoulMaxCp)` = 2200〜2300 になる。
  ところがただの劣勢はクランプ上限の 2500 なので、
  **確定で詰まされる筋がただの飛車損より高くなる**。
  反則項は「1手番あたりの期待反則回数」(高々 `oppFoulCap` = 2回)しか見ておらず、
  相手が反則負けするのに必要な残り10回ぶんの予算を表現していないので、
  終端の敗北に対する割引としては桁が合わない。
  短絡を無条件に戻し、「相手が先に反則負けする」逃げ道は**モデル化しない**
  (既知の近似)と明記した
- **`opp_node` の ±2500 クランプが、ply=1 より深くで見つけた詰みを消していた** —
  `oppmodel > 0` にすると stage2 の評価は必ず ply=1 の `opp_node` を通る。
  そこで混合値を ±2500 に丸めていたため、子が返した詰み(±3000)が
  通常評価の上限と同じ値に潰れ、**詰み筋が「ふつうの優勢」に見えて選ばれなくなる**
  (例: `p_legal` 0.95 の詰み 2375 < `p_legal` 1.0 のふつうの優勢 2500。
  `oppmodel 0` なら同じ詰みが 3000 で届いて 2832 となり勝つ)。
  混合値は子を `squash_cp` してから重み付けしたもので**すでに squash 済みの空間**に
  いるので、クランプを ±3000 に広げ、`DSearch::rootMixed` を立てて
  think() 側で二重に squash しないようにした

> **この2つの修正は `oppmodel > 0` 側の挙動を変える。**
> `oppmodel 0` の経路は完全に同一なので既定の挙動と対照側は変わらないが、
> **1.4〜1.9章の `oppmodel 1` 側は「詰みが見えない」ハンデを負ったバイナリでの
> 測定**だったことになる。修正後に測り直した結果は 1.10章。

#### 5度目のレビューで直した不具合(混合空間の境界が2か所で曖昧だった)

4巡目で「混合値は squash 済みの空間にいる」と整理したが、その空間の**境界**が
2か所で詰みの符号化とぶつかっていた。どちらも既定(`oppmodel 0`)では起きない。

- **反則項で「ただの優勢」が詰みの符号と衝突する** — 反則項 `v -= min(fG·eFoul, oppFoulMaxCp)`
  は常に v を下げるので、`foulgain > 0` だと相手視点で大きく負けている局面が
  クランプの −3000 に張り付く。ところが **±3000 は `squash_cp` が詰みに使う符号**
  なので、think() から見ると「証明された詰み」と同点になり、
  0〜4cp の乱数タイブレークが**詰みでない手を詰みより上に置きうる**。
  混合値のクランプを **±2900(`MIX_MAX`)** に下げ、
  ±3000(`MATE_MIX`)を詰み専用に空けた。100cp の余白は乱数タイブレークの幅より十分広い
- **`oppmodel 2` で子の混合値を二重に飽和させていた** — 子の部分木の中に
  さらに深い相手ノードがあると、その返り値は既に混合空間にいる。そこへ
  `squash_cp` を掛けると (2500, 2900] が 2500 に丸められ、
  深いところの詰み寄りの評価が消える。4巡目の `rootMixed` は think() の境界
  (ply==1)しか見ていないので ply≥3 を救えていなかった。
  **べき等な `squash_for_mix`**(詰み→±3000、それ以外→±2900にクランプ)を
  導入して、混合の内側ではこちらを使うようにした

> **既定の挙動は変わらない**(`squash_for_mix` は `opp_node` の中でしか呼ばれない)。
> `oppmodel 1` に対しても影響は限定的で、詰みが絡むノードと
> 評価が±2500を超える極端なノードでしか差が出ない
> (`oppmodel 2` の「深い相手ノード」の経路は `oppmodel 1` では発生しない)。

## 2. 相手の反則を観測として使う — 重み付き粒子(SIR)

### 2.1 捨てている証拠

現状の更新則は「相手の反則: 制約なし(カウントのみ)」だが、これは正しくない。
相手が反則した ⇔ 相手の意図した手が真の盤で不正だった ⇔
**相手の駒配置(=粒子)によって起こりやすさが違う**。たとえば相手の大駒が
こちらの駒立ちに向いている粒子ほど、経路封鎖の反則は起きやすい。
つまり `P(OppFoul | 粒子) = 1 − p_ok(粒子)`(§1と同じ量)であり、
これは粒子の尤度としてそのまま使える。棄却(0/1)では表現できないので、
重み付き粒子が前提になる。

同様に、いまは棄却しかできない弱い証拠が重みなら使える:

- 相手が反則**しなかった**(普通に指した): 尤度 ∝ p_ok(粒子)。
  「相手が詰まりやすい配置」の粒子を正しく減点する
- スライダー移動の反則からの演繹(経路のどこかが埋まっている、ピンの可能性あり):
  現状は合成粒子の棄却検査のみ。重みなら確率的なまま効かせられる

### 2.2 設計

- `Particle` に `logw` を追加。イベント適用時に上記の尤度で更新する。
  相手手のサンプリングは現状どおり整合手の中から方策で引き(提案分布)、
  重みには整合手の質量を掛ける(標準的な importance sampling の分解)
- ESS = (Σw)²/Σw² が粒子数の半分を切ったら系統的リサンプリング。
  `think()` 側は `p_legal` と探索値の期待を重み付き平均に変え、
  `pick_particles` は重みに比例した系統抽出にする
- 合成粒子の初期重みは、演繹の「空きらしさ」(`stale`)に対する配置の尤度で与える。
  4.5章の知見(中盤の信念は7割が合成粒子)のとおり、**重みが一番効くのは合成側**
- フラグ `sir 0/1`(既定0で導入)。重みの縮退(1粒子に集中)は
  ESS 診断行を足して監視する

### 2.3 計測と採用ゲート

`king_acc` / `occ_rec` / `brier` の3点が同じ向きに改善すること(勝率は参考値)。
特に相手の反則が多い局面(王手をかけた直後など)で `king_acc` が動くはず。
§1の fG は p_ok の較正に依存するので、§1採用後にやるほうが効果を測りやすい。

## 3. 計算資源 — 並列化と探索の底上げ

### 3.1 粒子並列(`threads`)

粒子はほぼ完全に独立なので、並列化の筋は素直。実対局の予算(2.4秒/手)なら
8コアで粒子数を256→512以上に増やしてなお深さを維持できる。

- **stage1/stage2**: いまは候補ごとに粒子を選んでいるが、同じ粒子の `Position` に
  複数スレッドが `do_move` すると競合する。ループを**粒子側で分割**し
  (スレッドが粒子を占有し、その粒子上で全候補を評価)、候補ごとの合計は
  スレッドローカルに積んで最後に固定順で合算する(浮動小数の和の決定性を守る)
- **再生成**: ワーカーごとに独立の PRNG でリプレイし、完成粒子をmutexで回収。
  墓場はスナップショットを読み共有する
- **決定性**: A/B の再現性のため、乱数は (seed, 手番, 粒子index) から決める。
  スレッドスケジュールに依存する挙動を残さない(4.5章の計測規律の延長)
- やねうら王はマルチスレッド前提の設計なので `Position` 毎に独立なら安全だが、
  `LONG_EFFECT` と MaterialLv9 評価のスレッド安全性(グローバル状態の有無)は
  導入時に確認する
- 副次効果: アリーナの回転も速くなる。§7の「60局×3seed」ゲートの実行コストが
  下がるので、**全施策の較正ループが速くなる**

### 3.2 DSearch の底上げ(TT・オーダリング)

- スレッドごとの小型置換表(2^20エントリ、`pos.key()`、depth優先置換)、
  killer/history、stage2 の反復深化に aspiration window。
  現状の MVV-LVA だけのオーダリングでは深さ6でも枝刈りが利いていないはず
- 期待効果は「同じノード予算で+2〜4プライ」。§1の `oppmodel 2` は
  αβの枝刈りを一部捨てるので、ここで取り返す関係にある
- やねうら王本体の `YaneuraOuWorker`(LMR・TT・history完備)への差し替え(design.md
  5章の4番)は配線コストが大きいので、**自前TTで足りるかを先に測る**。
  深さがなお律速ならそのとき本体接続に投資する

### 3.3 計測と採用ゲート

- 並列化: 同一設定のA/Bで勝率中立(決定性・正しさの確認)→ nodes/s ≥ 4×(8コア)
  → 粒子数・`stage2Samples` を増やした設定で対旧設定勝率
- TT: 固定予算での `depthReached` 分布と、対TTなし勝率

### 3.4 実装(2026-08-31)と実測

§3.1(`threads`)と§3.2(`tt`)を実装した。どちらもフラグの後ろで、
既定値(`threads 1` / `tt 0`)ではコード経路も従来と完全に同一。

実装が設計と違う点:

- **stage1/stage2の並列化**は設計どおり粒子側で分割(ジョブ=(候補,粒子)を
  粒子グループにまとめ、同じ粒子は必ず同じスレッドが処理する)。ただし
  合算はスレッドローカルではなく**ジョブごとの値を配列に保存してから固定順で還元**
  する形にした。これでグループの動的スケジューリング(atomicカウンタ)と
  浮動小数の和の決定性が両立する
- **乱数を (seed, 手番, 粒子index) から決める**案はやめ、再生成ワーカーごとに
  (基準乱数, workerId) から導出した独立PRNGにした。時間門で打ち切る以上
  完全な再現性はもともと無く、「スレッドスケジュールに依存しない」のは
  評価値の還元順だけで足りる
- **TTの世代管理**: 値によるカットオフは同世代(=同じthink()呼び出し)の
  エントリだけに許す。局面評価は手番内では(局面,深さ)の純関数だが、
  手番をまたぐと oppFouls 依存の項(foulGain)が変わりうるため。
  旧世代エントリはオーダリングのヒントとしてだけ使う。historyは手番ごとに半減
- スレッド安全性: MaterialLv9評価・mate_1ply・LONG_EFFECTにグローバル可変状態は
  なく、`Position`毎に独立なら安全(ThreadSanitizerでoppmodel 0/1のアリーナを
  走らせて警告0で確認)

## 4. 相手priorの較正

`fast_policy_score` の重み(PUSH表・中央志向・成り+300など)は勘で置いた未較正の値。
これは信念のフィルタ・再生成・合成、そして§1採用後は**探索の相手ノード**まで、
同じ関数が4箇所で使われる急所なので、較正の投資効率が高い。

- **教師データはアリーナにある** — 審判は完全情報を持ち、相手(heuristic / belief 両方)の
  実際の指し手を知っている。`arena dump <file>` を追加して
  (相手視界の特徴量, 選ばれた手) を JSONL で吐き、オフラインで多項ロジスティック
  (softmax回帰)を当てる。特徴は現行の項+「直前に駒を取ったマスへの吸引」
  (取り返し・追撃の傾向)・「王手されたときの玉周りの手の選好」あたりから始める。
  出力は重み表として `fast_policy_score` に貼り戻す(依存を増やさない)
- **限界を明記しておく** — 実対局では相手の指し手は観測できないため、
  サイトの人間・他botへの直接の教師あり学習はできない(信念でEMを回すのは将来課題)。
  アリーナ集団(heuristic=サイト内蔵bot相当、belief=強い相手の代理)への
  フィッティングに留め、ε一様混合は頑健性のため残す。
  サイトが終局後に棋譜を開示するなら(bot-api仕様の確認事項)、
  ブリッジの対局ログ(JSONL、design.md 5章の7番)から実データで再較正できる
- 採用ゲート: held-out の log-loss が手書きpriorに勝つこと、
  そのうえでアリーナの `king_acc` / `brier` が改善すること

## 5. 反則経済の統一

反則の値付けが3箇所(自分の `foulCp`・相手の `foulOppW`・妨害の `blockCp`)に
散っていて、それぞれ別の式と較正状態を持っている。§1で相手の反則期待が
探索の中に入るのを機に、1つの関数に寄せる:

```
foul_value(f) = (foulBaseCp + foulStepCp·f) × 10/(10−f)    // f = その側の反則累計
```

- 自分側: 現行どおり `−foul_value(ourFouls)` × 信念品質の割増(relaxMean・粒子不足)
- 相手側: §1 の fG = `+foul_value(oppFouls)`。相手が反則予算を使うほど
  1回の価値が急騰する対称形になり、「相手を反則負けに追い込む」終盤の
  価値が自動で立つ。`foulOppW`(未較正・既定0)と `blockCp` はこの統一で退役させる
- 非対称性はフラグで残す: 相手の反則は**こちらの信念を壊さない**ぶん
  自分の反則より安い可能性がある。`foulGainScale`(設計時の既定1.0)で減衰できる
  ようにしてA/Bで決める

> **実測後**: fG は有害と判明したので `foulGainScale` の既定は **0**(無効)。
> §5の「反則経済の統一」は、少なくとも探索木の中で局面評価と同じ通貨で足す形では
> 成立しなかった。1.5 / 1.7 / 1.8章を参照。

## 6. 評価関数 — 当面据え置く判断

NNUE(halfKP)への差し替え(design.md 5章の6番)は**優先度を下げる**。根拠:

- 通常将棋で学習した評価は、ついたて将棋で意味の違う概念(玉の安全度は
  「見えているか」に依存する・駒の当たりは相手に見えない)を誤った重みで持ち込む
- MaterialLv9 は外部ファイル不要で速く、粒子×候補×深さの積で呼ばれる本エンジンでは
  速度がそのまま粒子数と深さになる
- §1が入ると「探索が評価に何を求めるか」自体が変わる(相手の反則期待が
  値の主成分の一つになる)ので、評価関数の比較はその後のほうが意味がある

代わりに、ついたて将棋固有の軽い評価項を backlog に置く: 玉の秘匿度
(相手のprior的な攻め筋から外れたマスにいる玉への加点)、駒取りによる情報漏れ
(取ると自駒の位置が1マスばれる)の減点など。いずれも §1 のprior基盤の副産物として
安く作れるが、較正コストがあるので個別にゲートを課す。

## 8. やらないこと(非目標)

- **IS-MCTS等への探索の作り替え** — 確定化αβはやねうら王の資産(合法手生成・
